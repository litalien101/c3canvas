# API Contract (CC3 Character Workflow)

Prefix: `/api/v1`. JSON payloads use UUID strings and ISO-8601 timestamps. FastAPI publishes the runtime OpenAPI schema.

## Accounts and project access
- `POST /auth/register` creates a local username/password account; usernames are case-insensitive, passwords require at least 12 characters, and the API stores scrypt password hashes. Local development allows registration by default; `ALLOW_ACCOUNT_REGISTRATION=false` disables it. In production registration defaults to disabled and must be explicitly enabled for initial provisioning.
- `POST /auth/login`, `GET /auth/session`, and `POST /auth/logout` issue, inspect, and revoke an opaque server-side session. The session token is held in an HttpOnly, SameSite=Strict cookie with a seven-day expiry. Unsafe requests to project routes and logout require the session's CSRF token in `X-CSRF-Token`.
- Project creation records the authenticated account as owner. List, summary, read, update, delete, upload, chat, approval, checkpoint, and modeling operations are scoped to that owner. Requests for another account's project return `404 PROJECT_NOT_FOUND`.
- Existing projects without an owner are assigned to the first account registered after migration. Later accounts do not gain access to those projects.
- Development auth/project routes accept loopback peers only. Remote access requires `APP_ENV=production`, HTTPS termination, and explicit `ALLOWED_ORIGINS`; production account registration is disabled by default.

## Projects and assets
- `GET /assets/eyes` lists 14 integrity-verified eye assets, each pinned to a generated eye-only GLB. `GET /assets/eyes/{asset_id}/preview?sha256={generated_hash}` serves only the selected eye's verified browser preview, preserving eye surface, occlusion, tearline, and materials. The browser overlays it without Blender or a compiled character and initializes a replacement overlay to the active CC5/CC3+ preset before crossfading it into view. Proxy deltas are in meters while eye asset vertices use centimeter-like local coordinates under a 0.01 group scale; convert deltas into eye-local units before applying them. Preset accessory deltas must be mapped from the matching proxy eye surfaces, not treated as replacement-eye vertex indices.
- `GET /assets/skins` lists locally installed integrity-verified skin cards. `GET /assets/skins/{asset_id}/preview?sha256={hash}` serves a 256px WebP card image; `GET /assets/skins/{asset_id}/textures/{material}/{map}?sha256={hash}` serves an allowlisted 1024px-or-smaller WebP diffuse or lossless PNG normal preview. Skin normal-map strength is pinned to 0.35 in both browser preview and the Blender material library. Full-resolution PNG maps and the pinned Blender material library remain separate and are used for final compilation. The initial `skin_cc3plus_female_1` card is compatible only with `character_cc5_rlcc3plus_all_morphs_v1`. Paths are fixed by the local manifest, hashes are checked, and client-supplied paths are never used.

- `GET /models` returns lightweight metadata for installed allowlisted character models (CC3 Female/Male and CC3+ Female). The character chooser presents CC3 Female as the default **Basic** workflow and CC3+ Female as **Advanced**; both follow the same project and approval steps, while Advanced provides more controls and may use more resources. The catalog verifies preview hashes and checks source-file availability without hashing large source files on every startup; the Blender worker verifies full source hashes before import/application. Entries include pinned hashes, morph-control counts, `morph_preview_mode` (`client` or `server`), optional integrity-checked `morph_proxy_sha256` and `morph_delta_sha256`, available `morph_presets` (27 allowlisted CC3+ body and head presets), and the requirement for plan approval before import; they omit the larger morph-control specifications.
- `GET /models/{asset_id}/morph-controls` returns the manifest-backed morph-control specifications for one available model. The browser requests controls for the startup or selected asset rather than downloading every model's controls with the catalog.
- `GET /models/{asset_id}/startup-preview?sha256={source_hash}&preview_sha256={preview_hash}` serves an optional integrity-checked lightweight preview with no morph targets after the user selects or opens a project. The catalog includes `startup_preview_sha256` when one is installed. The lightweight Female preview keeps the source geometry, caps textures at 1024px, and avoids downloading the full morph library until the user edits a slider.
- `GET /models/{asset_id}/morph-preview?sha256={source_hash}&preview_sha256={preview_hash}` serves the integrity-checked editable preview on demand. CC3 previews use Meshopt compression and retain browser-local morph targets; the full source GLBs remain unchanged for Blender imports. The browser requests this larger asset when the user first adjusts a CC3 morph. The CC5/CC3+ preview is static and contains no morph targets. Neither preview endpoint accepts filesystem paths.
- `GET /models/character_cc5_rlcc3plus_all_morphs_v1/morph-proxy?sha256={source_hash}&proxy_sha256={proxy_hash}` serves the optional integrity-checked CC5/CC3+ browser proxy. `GET /models/character_cc5_rlcc3plus_all_morphs_v1/morph-deltas/{control_id}?delta_sha256={delta_hash}` serves one manifest-allowlisted sparse signed control delta and rejects stale hashes before applying immutable caching. Control IDs are URL-encoded as path values; the route supports slash-containing manifest IDs and still requires an exact manifest allowlist match. The proxy uses source topology without subdivision so each cached control maps directly to its source vertices; deltas load on demand and are combined locally. When the verified proxy is installed, the browser also uses it as the CC5/CC3+ base preview so slider edits do not swap the viewport to different topology. If the local proxy artifacts are absent or fail integrity checks, the catalog keeps the server-preview mode. These routes do not accept filesystem paths.
- `GET /models/character_cc5_rlcc3plus_all_morphs_v1/morph-presets/{preset_id}/delta?delta_sha256={delta_hash}` serves the allowlisted sparse delta for an installed CC5/CC3+ body or head preset. A preset appears only when its pinned source and generated proxy delta are available and integrity metadata matches.
- The startup viewport displays the Female model read-only without creating a project or importing into Blender. Morph changes remain local until explicitly saved to an imported project.
- `GET /health` reports API/persistence health and `blender_available` separately, plus `blender_error` when Blender is missing or misconfigured. Draft and planning routes remain usable in either case.
- `POST /projects` creates a lightweight persisted draft for an installed model, owned by the authenticated account, and does not require Blender. It creates no Blender scene, component, or geometry.
- `POST /projects` accepts `base_model_asset_id`, defaulting to `character_cc3_morphs_v1` for existing clients. The selected ID is persisted in SQLite and returned on project reads.
- `GET /projects` lists saved projects; the browser starts on a welcome screen with no project selected or model preview mounted, and never automatically opens or mutates a project.
- `GET /projects/summary` returns only project ID, name, selected model ID, and whether a character has been imported. The browser uses this compact response for its saved-project menu instead of downloading full scene histories.
- `GET /projects/{project_id}` returns the project manifest and phase state.
- `DELETE /projects/{project_id}` permanently removes the owned project, its persisted state and checkpoints, reference uploads, and per-project Blender workspace. Active projects do not expire automatically; deletion has no trash or recovery window. If file cleanup fails, the API returns `500 PROJECT_CLEANUP_FAILED` and retains the project record so the owner can retry.
- `PATCH /projects/{project_id}` updates project metadata.
- `PATCH /projects/{project_id}/draft-morphs` accepts `expected_draft_revision` and the complete selected-manifest morph map. It validates every control ID and per-control range, saves the map and increments `draft_revision` without changing `scene_version`; stale revisions return `409`. Draft writes are rejected once the character has been assembled.
- `PATCH /projects/{project_id}/draft-appearance` persists selected `eye_asset_id`, `body_preset_id`, `head_preset_id`, and `skin_asset_id` without changing `scene_version` or invoking Blender. Eye IDs, installed CC5/CC3+ presets, and skin IDs are integrity/allowlist validated against the project's model. Draft appearance changes are rejected after compilation. Omitted `skin_asset_id` is preserved for older clients.
- The same draft-appearance route accepts optional `skin_paint_strokes`, a complete bounded list of paint/erase operations on the four allowlisted skin material regions. Each stroke validates its tool, color, radius, opacity, and normalized UV points; points may include pressure in `[0.05, 1]`, defaulting to `1` for legacy clients. Strokes require a compatible selected skin and are persisted with the draft. Changing or clearing the skin clears its strokes unless the request explicitly supplies a new list. Compile accepts only the strokes matching the saved draft and applies them after the pinned skin materials; draft updates never invoke Blender.
- Hair routes and operations are not currently supported; legacy hair asset and draft endpoints are not exposed.
- `PATCH /projects/{project_id}/draft-skin` accepts `expected_draft_skin_revision` and the complete version-2 semantic definition. It validates tone, roughness, and freckle density, size, and strength in `[0, 1]`; undertone in `cool | neutral | warm | olive`; and freckle color as a six-digit hex value. Version-1 definitions are upgraded with freckles disabled. Freckles use a saved deterministic seed on the head diffuse map only; no cheek/nose mask is claimed. A compatible skin is required. Stale revisions return `409`; writes persist without changing `scene_version` or invoking Blender.
- `POST /projects/{project_id}/skin/interpret` accepts a bounded natural-language prompt for the selected compatible skin and returns a validated partial patch, preview definition, changed-property list, and explanation. The route uses the server-side Copilot bridge and never persists the proposal; the client must explicitly apply it through the draft-skin route. Supported semantics are tone, undertone, roughness, and head-map freckles; other regional or generated effects remain unsupported.
- `GET /projects/{project_id}/preview` serves the project GLB after the selected character is imported. This fast viewport preview omits morph targets; Blender compresses preview geometry with `EXT_meshopt_compression` when the installed exporter supports it, so browser clients must enable a Meshopt decoder. A legacy preview is regenerated from the saved scene once, without changing its scene version. If the installed Blender exporter cannot omit morph targets, the API records that capability fallback and avoids repeating the export on later requests.
- `POST /projects/{project_id}/morph-preview` accepts the complete manifest morph map for an imported, unbaked server-preview character (CC5/CC3+ when the optional local proxy is unavailable). It validates control IDs and ranges, applies the values in an isolated temporary workspace seeded with the saved scene, and returns a GLB without changing the saved scene, project record, or scene version. A preview already running for that project returns `429` with `Retry-After`; the browser retries the latest slider values.
- `POST /projects/{project_id}/references` validates and stores a supported image; `GET` lists reference metadata and `DELETE` removes an uploaded reference.

## Planning and approval

- `POST /projects/{project_id}/plan` creates the deterministic CC3 character plan.
- `PATCH /projects/{project_id}/plan` updates the editable plan before approval, with scene and plan revision checks.
- `GET /projects/{project_id}/phases` lists phases.
- `POST /projects/{project_id}/phases/{phase_id}/approve` requires the current scene version and an awaiting-review phase. Approval is enforced server-side.

## Modeling tools

`POST /projects/{project_id}/modeling-tools` accepts only typed, allowlisted requests:

- `import_base_model` is the explicit final Blender compile action. It accepts only the project's selected, installed model (`character_cc3_morphs_v1`, `character_cc3_male_morphs_v1`, or `character_cc5_rlcc3plus_all_morphs_v1`), requires an approved reference plan, and compiles the pinned asset in Blender. The API passes the saved complete draft morph map (or neutral values), saved body/head preset selections, saved eye selection, and compatible skin together; the worker validates and applies them before writing the first committed scene and preview. The skin worker accepts only local manifest assets and never receives browser filesystem paths. The CC5/CC3+ worker appends the manifest-pinned `.blend` source rather than loading its full morph set into the browser.
- `attach_eye_asset` is rejected with `DRAFT_PREVIEW_ONLY`; selecting an eye is a browser preview and draft update, never a standalone Blender operation.
- The selected body and head presets are applied during the same compile operation, with a dedicated shape key on `CC_Base_Body` and transferred companion keys on the separate face meshes for each selection; both IDs are stored on the body component.
- `apply_cc3_body_preset` accepts the CC5/CC3+ body component, complete morph map, and allowlisted `preset_ids` containing `body` and `head` selections (each may be `null` to clear that kind). The API checkpoints before updating Blender and component metadata; the browser's Undo restores its previous preview selection until saved. The operation transfers each preset's body surface displacement to all five separate eye/occlusion/tearline/teeth/tongue meshes using nearest-surface interpolation. It is reversible by removing its dedicated keys, and checkpoint restore remains available. Head presets use the same CC5 body mesh topology but contain their own pinned head-shape offsets.
- `apply_cc3_morph_controls` accepts the body component ID, matching asset ID, and a complete map of that asset's manifest control IDs to finite values within each control's supported range. Up to 4,096 controls are accepted. The API checkpoints before applying values and updates the scene version and preview. The CC5/CC3+ operation applies matching keys on every affected character mesh.
- `bake_cc3_morph_controls` accepts the same scoped complete morph map, applies its combined shape, and removes editable shape keys. The CC3 assets bake the body mesh; the full CC5/CC3+ asset bakes all six character meshes. The API checkpoints first, stores zero morph weights with a baked-state marker, and rejects later morph edits until that checkpoint is restored.

The Female asset provides 137 controls backed by 244 directional exports. The Male asset provides 143 controls backed by 254 exports; its source FBX has 13,286 body vertices and the runtime GLB imports as 14,647 vertices. The owner-supplied CC5/CC3+ asset provides 2,042 signed controls across six meshes and 5,574 shape-key operations. It is installed only when its source `.blend`, static preview, and shared manifest are present and their hashes match. The owner confirms rights to provide the CC5/CC3+ character with this application (2026-11-07); underlying third-party attribution or redistribution terms have not been independently documented. The Male asset remains private/local until its redistribution rights are confirmed.

After a project is explicitly created or opened, the browser preview uses the pinned source GLB and its manifest control specifications. CC3 draft previews use the integrity-pinned morph asset for local edits. When the optional CC5/CC3+ proxy is installed and verified, the browser lazily fetches sparse deltas for changed controls and updates its local high-detail proxy; otherwise, CC5/CC3+ draft sliders remain disabled rather than invoking Blender. Draft morphs, appearance selections, semantic skin definitions, and paint strokes persist to SQLite without changing `scene_version` or starting Blender. Only explicit **Save / Compile** or export compiles the saved choices together. The welcome screen does not load a character preview or create a project.

The CC3 source GLB stores body morph targets on `CC_Base_Body`; eyes, teeth, and tongue are separate skinned meshes. Three.js may import the GLB primitives with numeric suffixes, so the browser groups matching body chunks and blends nearby body-vertex displacement samples across each facial mesh surface after armature skinning. The CC5/CC3+ source is a Blender project with keys on multiple meshes, and the worker applies each key to every matching mesh. Saving applies the validated morph controls to Blender.

Each operation declares an `operation_id`, `expected_scene_version`, `scope_component_ids`, `dependency_component_ids`, and typed arguments. Unknown operations, removed legacy tools, extra fields, client paths, and code are rejected. Repeating an operation ID with the identical request returns its recorded result, even if the scene has since advanced; reusing that ID with different request data returns `409 OPERATION_ID_REUSED`.

`GET /projects/{project_id}/operations` lists operation history and preserves historical tool names for read-only display; this does not expand the typed request allowlist. `GET /projects/{project_id}/checkpoints` lists checkpoints; `POST /projects/{project_id}/checkpoints/{checkpoint_id}/restore` restores a saved scene while advancing the scene version monotonically.

## Chat and planning provider

- `GET /copilot/status` reports local bridge availability without exposing tokens.
- `GET /projects/{project_id}/chat` lists persisted messages.
- `POST /projects/{project_id}/chat` requires an available configured local Copilot bridge for chat responses. If unavailable, the API reports an explicit error and does not fabricate a reply.
- A non-plan chat request supplies the assistant with up to 64 request-relevant manifest-backed morph controls and ranges, their current values, compatible installed appearance assets, compile/editability state, and registered guidance targets. The API validates proposals against the complete selected-model manifest. Reference image bytes are not sent.
- For a direct slider-location question (for example, “Where are the sliders?”), the API supplies registered `morph-library` guidance even if the Copilot reply is plain text. The browser opens Body Morphs and selects a real control; this navigation creates no proposal and does not change draft or scene state. If morph editing is unavailable, the guidance says so.
- A structured assistant turn has `message`, `morph_updates`, `appearance_updates`, and optional `guidance`. Morph proposals are limited to 32 known controls and finite in-range values. Appearance proposals accept only `eye_asset_id`, `skin_asset_id`, and `body_preset_id` with compatible installed IDs (or `null` only for an explicitly requested clear). Compiled projects reject appearance changes; non-editable/baked projects reject morph changes. Guidance targets must exactly match a registered library, control, asset, or workflow target.
- The response includes `assistant_proposal` and/or `guidance` when present. These are suggestions, not mutations. The browser requires an explicit user action and applies choices through the existing draft APIs; chat itself never calls Blender, approves a phase, or compiles. `interaction_warning` explains when a plain-text fallback produced no actions. Malformed or invalid structured output returns `502 INVALID_AI_INTERACTION` without persisting that turn.
- The structured proposal and guidance payloads are response-only and are not persisted in chat history; persisted history contains user/assistant text. Users can reopen guidance while the current response remains in the workspace.
- The serialized assistant context is limited to 32,000 characters; oversized context fails with `413 CHAT_CONTEXT_TOO_LARGE` rather than being silently truncated.
- A plan request uses the configured text model when available and otherwise the deterministic CC3 template planner. The planner records provider metadata and clearly states that stored reference images were not analyzed.
- `DELETE /projects/{project_id}/chat` permanently clears that project's chat messages.

Provider tokens remain server-side. The API does not send reference image bytes to the text-only Copilot bridge.
