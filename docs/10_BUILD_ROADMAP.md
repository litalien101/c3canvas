# Build Roadmap

The character workflow is one deliberate vertical slice: a welcome screen with explicit project create/open actions, followed by a persisted browser draft, live browser previews for supported edits, plan approval, and an explicit final save/compile of the complete draft in Blender. The character viewport and preview load only after the user creates or opens a project. Draft editing does not import geometry or start Blender; after compilation, only explicit supported scene operations may invoke the worker. Do not reintroduce assemble-first eyes, simulated geometry, or unpinned base-model imports. A separate early Object Workshop slice uses bundled CC0 model bases for its furniture, wall, and shield presets plus a parametric cube. Its browser-only Masonry generator creates bounded editable brick walls and paver roads; it does not imply Blender-equivalent modeling capabilities.

## Current supported slice

- Local username/password accounts, private owner-scoped projects, CSRF-checked mutations, and explicit sign-in/sign-out are supported for loopback development.
- React + TypeScript welcome screen with new-character setup and saved-project reopening; no project is created or automatically selected at startup.
- The editor and integrity-pinned character preview mount only after an explicit project create/open action.
- Dark navy three-column character editor with a persistent, collapsible Chat panel, live central viewport, and resizable right editor. The layout also adapts to a zoomed visual viewport so editor columns remain reachable instead of being clipped; in the compact zoom-fit layout, Chat starts collapsed to give the viewport and character controls more room and remains available from its labeled launcher. New/Open Project and Save / Compile remain explicit header actions; category tabs expose existing editor functions, and only manifest-backed controls and installed presets are shown.
- SQLite projects, saved plans, reference-image records, component manifests, operations, and checkpoints.
- Lightweight draft creation, deterministic model-specific plans, complete manifest-backed morph autosave with optimistic draft revisions, and plan approval do not require Blender.
- Approval is a real gate but does not start Blender. The user explicitly saves/compiles the persisted draft only when ready.
- Asset-specific pinned character import in the local Blender worker. Female remains the backward-compatible default; Male and CC5/CC3+ appear only when their matching manifests and integrity-checked local assets are installed.
- New character setup offers **Basic** (CC3 Female, preselected) and **Advanced** (CC3+ Female) as plain-language workflows. Both share the same project flow; Advanced exposes more shaping controls and can require more system resources. The CC3 Male remains an additional installed model option.
- Final compile passes the saved draft morph map, body/head preset selections, and selected eye to the worker in one operation before the first scene and preview are committed.
- Browser-local preview for CC3 manifest-defined morph sliders and, when its verified local proxy is installed, CC5/CC3+ sliders using lazily cached sparse deltas. CC5/CC3+ uses the same proxy topology for its base and edited previews to avoid a visible topology swap when a slider changes; its browser proxy build caps nail and eyelash normal maps at 512 px without changing source-character textures or morph topology. Without the proxy, CC5/CC3+ draft sliders remain disabled and assembled projects use the debounced server-preview fallback. Explicit save applies values to Blender after project assembly. Reset restores the last saved values. Baking freezes the combined slider shape into the body mesh, removes editable morph keys, and keeps a pre-bake checkpoint available for restoration.
- The editor header's Undo/Redo actions cover the last 50 morph-value edits only, including slider gestures, morph resets, the Elven Ears preset, and applied assistant morph proposals. A slider drag or keyboard adjustment is one history entry; history resets when changing projects. Undo/redo update the browser preview and, in an uncompiled project, the autosaved draft. For compiled characters they change only the local preview until the user explicitly saves morph changes to Blender. These controls do not undo skin, eye, body/head preset, paint, or Blender operations.
- CC5/CC3+ only: the Presets category offers up to 27 integrity-pinned body/head presets from `source_archive/presets/` when each source and generated browser delta is available. Cards preview and persist the selected body and head presets in the browser/API; final compile applies both selections as dedicated `CC_Base_Body` shape keys plus transferred keys on the five separate character meshes.
- CC5/CC3+ only: the Ears category offers an **Elven Ears** starter preset composed of verified native pointed-ear, height, and angle morphs. It changes only the draft morph map, previews through the existing verified proxy, and compiles with the saved morphs; it is a native morph blend, not a custom ear sculpt.
- The Eyes category offers 14 integrity-pinned eye-only GLBs. Selecting an eye loads only that eye's browser preview, preserving the eye surface, occlusion, tearline, and materials; it hides only default eye meshes in the base preview. The choice persists in the draft and is imported only during final compile. With the CC5/CC3+ proxy, a replacement overlay is brought to the active preset/morph pose before its crossfade. Proxy-meter deltas are converted to the eye asset's centimeter-like local units before the overlay's 0.01 scale is applied.
- Hair generation and pinned-hairstyle preview/attachment are currently removed and unsupported. The editor has no Hair category, draft hair settings, API routes, or Blender worker operations; future hair work must be designed and shipped as a separate documented slice.
- The Skin category offers only locally installed, integrity-pinned skin packages compatible with the selected character. The CC3+ Female card uses reduced WebP diffuse and lossless PNG normal previews (1024px maximum, 256px card image) for the head, body, arms, and legs in the browser draft; the normal-map strength is limited to 0.35 in both preview and compiled Blender materials. In the draft viewport, users can paint, scatter freckles, or erase on those four UV-mapped regions with adjustable color, 1 px through 96 px brush sizes, and 1%-100% opacity. Full-body hit detection canonicalizes `Std_Skin_Head`, `Std_Skin_Body`, `Std_Skin_Arm`, and `Std_Skin_Leg`, including imported numeric material suffixes, and supports both grouped meshes and single-material GLTF primitives without scanning unrelated material slots. The CC3+ preview packs head, body, arm, and leg UVs into U tiles 0 through 3; browser preview maps and saved paint strokes subtract the matching material tile offset before using each local skin texture. Freckles are surface-painted UV strokes that can be placed on any exposed skin material region; semantic layer controls distribute the head-map pattern but are separate from manual strokes. A surface-following brush ring is shown at the raycast hit and replaces the native cursor only while the pointer is over a paintable character skin surface; outside the model, the normal pointer remains visible. Pen pressure is recorded per point and varies brush size and opacity. Large UV discontinuities split the stroke rather than drawing a line across unrelated texture regions. Each pointer gesture is previewed locally and saved as a bounded UV stroke list; undo removes the last stroke and Clear paint resets the list. Paint saves are serialized so release-time and rapid successive strokes cannot race or clear each other. Paint mode leaves OrbitControls available only when the pointer is outside the character; hovering the model blocks orbit, pan, and zoom so viewport gestures cannot interfere with painting, while middle-button drag, right-button drag, wheel zoom, and keyboard-modified left-button gestures remain available over empty viewport space. Paint, freckle, and erase edits persist with the selected skin and are applied to the full-resolution, hash-verified materials only during explicit final compile. Skin selection, painting, and approval never start Blender. Semantic alpha/layer brushes, redo, and a synchronized 2D UV editor are not implemented yet. The source FBX and generated local maps/material library remain outside the browser bundle and are not committed.
- The selected skin also exposes versioned draft controls for base tone, undertone, surface roughness, and deterministic freckles on the head skin UV map. Users can choose Natural scatter, Light dusting, Dense center, Cheek clusters, Sun-kissed, Constellation, or Mottled variation patterns. Density, size, strength, color, and pattern preview in the browser; the same seeded layout is applied to the pinned diffuse map only during final compile. Legacy drafts without a pattern normalize to Natural scatter. Users explicitly save manual edits; Copilot interpretation returns an explainable proposal that must be explicitly applied. Freckles are head-map wide, not cheek/nose-specific, because verified anatomical masks are unavailable. Redness, moles, pores, wrinkles, subsurface controls, and region-specific effects remain unsupported.
- The lightweight model catalog includes pinned hashes and morph-control counts. Fetch model preview geometry and manifest controls only for an explicitly selected project model. Load the larger browser-morph asset only when a slider is adjusted. Project GLB previews omit morph targets and use Meshopt compression where supported by Blender.
- Human approval in the Scene workflow inspector is required before final compile of the selected model in Blender; approval itself does not import or mutate geometry.
- Unified dark-slate and blue-accent character-editor layout with a 65px header, 109px labeled navigation, central viewport, fixed responsive right inspector, and direct orbit/pan/zoom gestures; Models, Scene Hierarchy, Properties, and Workflow are not dockable.
- Scoped typed API and worker operations; no arbitrary model-generated code.
- Reversible changes, GLB preview refresh, and component visibility controls.
- Context-aware chat responses can propose allowlisted draft morph/appearance changes for explicit user application and show dismissible guidance beside registered controls. Chat remains text/proposal-only and never starts Blender or bypasses approval/compile gates.

## Independent Object Workshop slice

- Chair, Stool, Table, straight Wall section, and Shield use locally bundled 1K PBR GLBs from CC0 Poly Haven assets; Cube remains a parametric primitive. Provenance (source, creator, and license) is recorded in the frontend asset catalog and shown in the inspector. Model scaling and local cage deformation operate on the imported mesh geometry; supported source parts remain separate editable hierarchy components.
- The standalone viewport supports component selection, transform tools, a localized geometry-deforming cage with resolution/influence/X-symmetry controls, and undo/redo. Imported assets retain their PBR materials, support material tinting, and are included in GLB exports with the same dimensions and cage edits as the preview.
- Browser autosave and validated editable JSON import/export preserve the scene; new objects are placed clear of existing geometry and legacy origin-stacked scenes are spread apart on load. Existing procedural preset parts are retained in a collapsed, hidden backup group when old scenes gain sourced bases; custom components and prior edits remain recoverable.
- The standalone Masonry preset generates rectangular running-bond or stack-bond walls and roads from separately named, selectable brick/paver components over a mortar/sand bed. Dimensions, unit sizes, joint width/fill, deterministic subtle piece variation, clipped edges, optional paired wall-end returns, per-piece grid snapping, and whole-assembly move locking are covered by focused model tests; layouts use the existing autosave, editable JSON import, and GLB export paths. Arbitrary path-based layouts, curved or multi-segment corners, herringbone, texture displacement, and physically simulated mortar remain future work.
- This slice does not yet include arbitrary mesh topology editing, user-supplied model import, booleans, a general modifier stack, UV editing, rigging, or animation. Extend it only through tested, documented slices.

## Next slices

### 1. Harden the CC3 modeling workflow

- API and worker tests cover Female and installed Male manifests, signed and one-sided morph values, scoped saves, scene-version checks, exact-request retries, and checkpoint restoration.
- Verify loading and error states in the browser against the local API; distinguish API connectivity from Blender availability, explain that Blender unavailability blocks compilation but not saved draft editing, and provide in-place retries for API, project/model catalogs, project-dependent eye/skin catalogs, manifest-backed morph controls, and failed preview asset loads.
- Keep reference images stored, list them in the project workflow with dimensions and remove controls, and clearly mark them unanalyzed until a real image-understanding provider exists.

### 2. Improve product reliability

- Implemented local account registration/sign-in, secure session cookies, CSRF protection, per-project ownership checks, and first-account adoption of legacy projects. Hosted identity management and login throttling remain future work.
- Project deletion permanently removes persisted project/checkpoint state, reference uploads, and the Blender workspace; active local projects do not expire automatically.
- Add worker resource limits, deployment isolation, monitoring, and recovery procedures.

### 3. Expand modeling only behind measurable gates

- Evaluate the quality and licensing of a next geometry operation before adding it.
- Keep each editable component identity stable and preserve unrelated components during scoped edits.
- Require tests, documentation, a visible status, and explicit human approval for each new phase.
- Do not claim production anatomical quality, UVs, retopology, garment simulation, or animation until verified.

## Retired workflows

The static OBJ preview, CC5 FBX import, mock body/garment placeholders, garment revisions, legacy eyelid/ear sculpt tools, and automatic project restoration are removed. Their source assets and public operations are not part of the active product.

## Definition of done for a slice

- Acceptance behavior is implemented with explicit errors and loading states.
- API schemas and worker allowlists agree.
- Focused tests cover behavior, scope, approvals, and failure paths.
- User-facing documentation matches what the product actually does.
- The browser build, API tests, and Blender worker tests pass.
