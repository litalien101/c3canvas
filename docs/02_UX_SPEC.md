# UX and Interaction Specification

## Welcome screen and character creator

The browser opens to a full-viewport, dark navy dashboard with restrained cyan and violet lighting and a faint, low-contrast perspective-grid overlay. A left navigation rail contains Home, Projects, Models, Tools, Settings, and Help; unavailable destinations are visibly disabled. The top bar shows API readiness and a clearly labeled workspace rather than a fabricated user account. The main hero centers the C3Canvas wordmark and supported draft-first workflow copy beside the supplied brand illustration. The project-backed AI Assistant includes starter suggestions that either open character setup or fill the prompt without sending it.

The dashboard has five rearrangeable cards: the welcome hero, AI assistant/chat, a clearly marked illustrative **Fantasy Realm** visual concept that is not a saved project, Recent Projects populated only from the API, and a draft/compile workflow explainer. Drag a card by its grip or use its move-up/move-down controls; the chosen order is saved in browser-local storage and can be reset from the top bar. The layout remains responsive as cards move. The concept panel's action starts the real character setup flow. Recent projects show up to three real saved projects with their model and draft/compiled state and expose loading and error states rather than fabricated projects, previews, or dates. The workflow panel describes existing draft-preview and explicit compile behavior.

At tablet widths, the navigation becomes a horizontal icon bar and the hero, assistant, and project panels stack in a scrollable dashboard. On narrow screens, the centered hero art and copy stack above the assistant and project panels. The assistant is part of the page layout rather than a floating window.

On a 1365×768 desktop, keep the 158px navigation rail distinct from the main dashboard. Place the hero and assistant in the upper row, with the assistant inset from the hero edge; align the three project/workflow cards in a lower row beginning about 468px from the top and ending about 58px above the viewport bottom. Use roughly 25px of left and 17px of right dashboard inset, with the lower cards around 242px tall. Keep the hero illustration within its upper row so it does not overlap the lower cards. Scale these proportions responsively rather than letting cards touch the viewport edges.

The welcome screen does not imply that unsupported modeling features are available. A first chat prompt stays in the composer while the user chooses an installed model; only after the user confirms project creation is the draft/plan created and the prompt sent through the project-scoped AI endpoint. Typing or opening the page never creates a project or starts Blender. Starting a character opens the installed-model chooser, with Basic (CC3 Female) recommended and Advanced (CC3+ Female) offered where available. Creating a project enters the character workspace and creates a saved draft/plan; it does not compile geometry. Opening a saved project is an explicit action. A Home action returns to the welcome screen only when draft edits are saved.

The create-project and character chooser dialogs use the dashboard's navy, cyan, and violet palette. The character chooser follows the supplied compact two-column reference: the title, character name (the saved project name), and installed base-model choices on the left; the supplied brand illustration and an accurate draft/approval/compile summary on the right. The reference's style and personality controls are not implemented: show any visual stand-ins as clearly unavailable, noninteractive placeholders, and keep the personality field and advanced options disabled. Do not imply that these choices affect a character. Keep the real model selection, name, and create action visible; on narrow screens, hide the decorative and unavailable placeholder areas and keep the real project controls usable without an internal scrollbar.

The current startup asset is a rigged CC3 base, not the armored fantasy character in the visual reference. Do not imply that clothing, skin, markings, or other unsupported content is present or editable. Show only manifest-backed morph controls; show the installed body/head preset library only when the compatible CC5/CC3+ model is selected.

## Desktop layout

- **Header:** 65px charcoal bar. On the left, the minimal C3Canvas monogram and title with the **Code · Create · Collaborate** tagline, followed by New Project and Open Project icon buttons. Open Project shows an accessible list of saved projects and is disabled when there are no other saved projects. Disabled undo/redo, explicit **Save / Compile**, and disabled Play remain on the right. Save / Compile is disabled until the plan is approved and Blender is available. Creating or opening a project is an explicit action; the initial preview does not create or restore a project.
- **Navigation:** a 109px Models/Scene/Materials/Lighting/Settings rail below the header. Models is selected at startup; unsupported sections remain disabled.
- **Viewport and editor:** at 1365×768, the responsive right editor is about 650px wide, leaving a roughly 600px interactive canvas between it and the navigation rail. On desktop, allow the user to resize the right editor by dragging its left edge; keep the editor at least 520px wide and preserve at least 320px for the viewport beyond the 84px navigation rail. The resize edge is keyboard operable with left/right arrow keys and has a visible hover/focus affordance. At tablet widths, stack the editor below the viewport. Use a dark charcoal studio background, soft radial illumination, a circular low-profile platform with subtle rings, and contact shadows. Do not show a perspective grid, orientation gizmo, empty-state card, or selection/move/rotate toolbar.
- **Right editor:** show Morph, Skin, Hair, Clothing, and Extras as typographic tabs; do not use category icons or artwork. Use compact uppercase semibold labels with increased tracking, a subtle blue glow and underline for the active category, and brighter text on hover. Morph selects the existing Body customization category; Skin selects the existing Face category; Extras selects the existing Accessories category. Preserve the existing category actions and accessible names. The Body editor uses three panes: a scrollable anatomy-category list; a searchable morph library with type filters, All/Favorites/Recent views, and compact cards; and selected-control details with its slider, reset, and related controls. Anatomy categories are inferred from manifest control names and are shown only when they contain controls. The Shoulder Front Crease morph card uses the supplied shoulder-front-crease reference image, scaled to show the full image without cropping; omit the separate card label because the image already includes its title. Morph cards are slightly shorter. Other cards continue to use their existing category illustrations. Search spans anatomy categories; type and library filters apply to the current category or search results. Basic mode is the default and shows up to 12 matching controls; Advanced shows all. Slider values preview immediately, but draft autosave waits until a pointer or keyboard slider interaction ends. Reset selected control, Reset category, and Reset all set the affected controls to neutral (0), including values already autosaved in the draft. Properties shows morph status, provides Reset all, and links back to the Body editor rather than duplicating the full slider library. Bake applies the current combined shape to the Blender mesh, removes its editable morph shape keys, and saves a pre-bake checkpoint; show a restore action while baked. Omit the retired torso-length control. Draft preview morph changes remain local until saved; saving and baking require an imported character in a project. Skin tones, presets, body markings, and armor are not implemented and must not be presented as working options.
- **Viewport controls:** pointer navigation works without selecting a toolbar mode: left-drag orbits by default, mouse-wheel zooms, and right-drag pans; middle-drag also zooms. The Orbit/Pan/Zoom toolbar optionally changes the left-drag action. A compact lower-center toolbar resets the camera, enters fullscreen, switches perspective/orthographic projection, and selects cool/warm studio fill lighting. Recording is visibly unavailable. Do not show the retired Camera/Pose overlay.
- **Tablet and mobile:** stack the viewport above the scrollable editor without horizontal page overflow. At tablet widths, retain the three editor panes side by side; on narrow mobile screens, stack the anatomy navigation, morph cards, and selected-control details vertically. Keep viewport navigation and the lower toolbar within the canvas; hide the unavailable recording action and use compact touch targets on small phones. Offset the assistant launcher from the bottom toolbar so they remain independently tappable.

## Project and approval flow

1. Startup loads the welcome screen, project summaries, and installed-model catalog without mounting the 3D viewport or downloading the character preview. The model preview and manifest-backed morph controls load after the user creates or opens a project. The larger editable morph preview is loaded only when the user adjusts a control.
2. The welcome screen’s **Start a new character** action opens project setup directly at the installed-model chooser. The user selects an installed model; the API creates a project and reviewable plan without requiring Blender or importing geometry.
3. The selected model's browser preview is available in the draft. Slider values are autosaved as a complete manifest map and draft revision; eye and preset choices are also persisted as draft appearance. CC3, eye, and verified CC5 proxy changes preview locally. If the optional CC5 proxy is unavailable, its sliders remain disabled rather than invoking Blender for a preview.
4. The user explicitly approves the plan. Approval is enforced by the API but does not start Blender or create geometry.
5. A separate **Save / Compile** action requires plan approval and Blender availability. The worker imports the selected pinned source, applies the saved slider map and preset, and imports the selected eye in one operation. Draft editing does not import geometry or start Blender. After compilation, the viewport switches to the saved GLB; later scene changes require explicit, supported worker operations.
6. The reference-plan card clearly states that reference images are stored but not analyzed.

Opening a saved project is an explicit action from the Open Project header button; the application does not automatically restore a project or mutate saved data on launch. Project approval and Blender build actions remain in the Scene workflow inspector.

## Assistant

The AI Assistant is open on the welcome screen and remains available in the character workspace. On the welcome screen, a first prompt is held until the user selects a model and explicitly creates a draft project; it is then sent to the project-scoped chat API. In the workspace, the assistant retains chat history and supports resizing and repositioning while open. Requests use the configured local Copilot bridge; errors are explicit, and the UI never fabricates assistant replies. Enter sends; Shift+Enter inserts a line break.

The assistant may return an answer with a draft-only proposal and/or contextual guidance. Render the answer and proposal as text, show the proposed morph values or appearance choices, and require the user to select **Apply to draft**. Applying uses the existing draft controls and save APIs; it does not invoke Blender, approve a plan, or compile. Compiled projects cannot receive appearance proposals, and unavailable morphs remain unavailable.

Guidance targets are stable, server-allowlisted identifiers for the morph library/control, eye or skin library/asset, preset library/asset, and workflow review area. On receipt, open the relevant category, scroll the target into view, and show a small dismissible tooltip pointing to that target. A slider-location question must open **Models → Body → Morphs**, select a real morph control, and explain where its amount slider appears—even when Copilot returns only plain text. Include a **Show guide** action in the assistant message so guidance can be reopened. If a target is not present, do not show a misplaced tooltip; report/retain the assistant message and allow a bounded retry while that editor content loads. Tooltips use ordinary escaped text, never model-provided HTML. The assistant must explain unsupported requests honestly; there is no installed age morph or aging-skin effect, so it may not promise a true aging transformation.

## States and capability boundaries

The interface distinguishes:

- Welcome screen, including API connection, saved-project loading, and error states; no model is loaded before an explicit project action.
- Explicit project create/open transitions into the character workspace; returning Home does not discard unsaved draft edits.
- No project selected versus an explicitly opened or newly created project.
- Plan awaiting approval, approved, draft autosave, Blender unavailable, and final compile in progress.
- Character draft and local preview versus assembled character, saved morph values, unsaved local edits, and baked geometry with its checkpoint-based restore action.
- Failed operations and recoverable saved project state.
- Copilot unavailable; no fabricated chat response.

Approval is required before final compilation in Blender; approval alone does not import geometry. Draft slider values, eye choices, and preset choices are project data, not saved Blender geometry. Eye previews use only the selected eye GLB and hide only the base preview's default eye meshes. Component visibility changes affect only the current preview. Unsupported categories, materials, skin, markings, pose editing, and unsupported geometry operations remain unavailable. CC5/CC3+ preset selection previews and persists locally; final compile applies it to Blender. Never describe a preview-only edit as Blender geometry or imply that a placeholder is a real model.

## Visual design

Use one midnight-slate theme throughout the workspace, project dialogs, and AI Assistant: base `#0e1118`, panels `#151a23`, raised surfaces `#1a202b`, primary text `#e7eaf0`, muted text `#9aa5b7`, and active blue `#438fff`. Keep success/warning/error colors reserved for status. Use restrained borders and consistent small radii. At desktop widths, preserve the 65px header, 109px labeled navigation rail, viewport, and editor proportions. Use compact spacing, visible focus, readable disabled states, reduced-motion support, and non-color status labels.
